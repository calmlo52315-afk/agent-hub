# AgentHub Runtime V2 重构方案

## 重构目标

解决当前系统存在的三个核心问题：

1. Claude Code 同时承担 Agent、Skill、Executor 三种角色，职责混乱
2. 简单任务与复杂项目走同一条执行链路，导致性能极差
3. 后续 Codex、自定义 Agent 接入后无法扩展

重构后目标：

* Agent = 角色
* Skill = 能力
* Provider = 实际执行器

实现：

* Direct Agent Chat
* Orchestrated Group Chat
* Skill Router
* User Defined Agent

统一架构。

---

# 一、目标分层

## Layer 1：Interaction

用户如何发起任务

### Direct Agent

用户：

@Claude Code 写一个 FastAPI 登录接口

或者：

@Codex Review 这个文件

特点：

* 用户明确指定 Agent
* 不经过 Planner
* 不经过 Orchestrator

链路：

User
→ Agent
→ Skill
→ Result

---

### Group Chat

用户：

开发一个博客系统

特点：

* 用户未指定 Agent
* Orchestrator 自动调度

链路：

User
→ Orchestrator
→ Planner
→ Skill Router
→ Agents
→ Result

---

# 二、Agent 与 Skill 解耦

## Agent

Agent 是角色

Agent 不直接绑定模型

例如：

PlannerAgent

CodingAgent

ReviewAgent

FrontendAgent

BackendAgent

TestingAgent

---

## Skill

Skill 是能力

一个 Agent 可以拥有多个 Skill

例如：

CodingAgent

拥有：

NativeCodegenSkill

ClaudeCodeSkill

CodexSkill

---

ReviewAgent

拥有：

RuleReviewSkill

CodexReviewSkill

---

PlannerAgent

拥有：

LLMPlannerSkill

RulePlannerSkill

---

# 三、Provider 层

Provider 才是真正调用外部能力

例如：

ClaudeCodeProvider

CodexProvider

OpenAIProvider

DeepSeekProvider

GeminiProvider

---

Skill 调用 Provider

而不是直接调用模型。

例如：

ClaudeCodeSkill
→ ClaudeCodeProvider

CodexSkill
→ CodexProvider

NativeCodegenSkill
→ OpenAIProvider

---

# 四、Skill Router

新增组件：

SkillRouter

职责：

根据 TaskPlan 选择 Skill。

---

输入：

task_type

complexity

language

workspace_required

review_required

---

示例：

simple code generation

↓

NativeCodegenSkill

---

medium task

↓

CodexSkill

---

project task

↓

ClaudeCodeSkill

---

禁止：

Planner 直接指定 Claude Code。

Planner 只负责规划。

SkillRouter 负责选择执行器。

---

# 五、Task Complexity

新增复杂度分类

simple

medium

project

---

simple

特点：

单文件

无上下文依赖

无需修改现有项目

示例：

写一个 Java Hello World

写一个 Python 排序函数

---

medium

特点：

多个文件

简单模块开发

需要代码审查

示例：

SpringBoot API

React 页面

---

project

特点：

多目录

需要理解项目

需要执行命令

需要 Workspace

示例：

博客系统

后台管理系统

重构项目

---

# 六、执行模式

execution_mode

只保留：

task

project

---

task

流程：

Planning
→ Coding
→ Review（可选）

---

project

流程：

Planning
→ Coding
→ Review
→ Packaging

---

Packaging

原 Artifact Stage 改名。

Artifact 仍然表示所有产物。

Packaging 仅表示：

压缩

部署包

项目快照

Bundle

---

# 七、Workspace

Workspace 不是 Artifact。

Artifact：

任何产物

代码

文档

图片

Diff

---

Workspace：

项目级文件系统视图

只在：

workspace_required = true

时显示。
