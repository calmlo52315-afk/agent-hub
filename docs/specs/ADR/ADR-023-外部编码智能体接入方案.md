# ADR-023 外部编码智能体接入方案
> 前置说明：现有ADR-001～ADR-015已落地运行时、智能体、能力契约、消息协议、任务回放、指标采集、状态机相关架构规范，但缺失**第三方编码智能体如何接入系统**的标准化方案；Claude Code、Codex已不属于通用大模型，本质是**外置独立编码运行时**，因此新增本独立ADR文档。
> 备注：若已有编号占用，文档编号顺延。

## 一、决策结论
AgentHub 采用外置编码智能体接入架构设计；
通过能力运行时（Skill Runtime）层对接集成 Claude Code、Codex；
各类第三方编码智能体统一作为**可被调度的能力单元（Skill）**接入，不作为系统内置智能体。

## 二、背景说明
当前项目MVP内置三类核心智能体：
```
编码智能体（Coding Agent）
评审智能体（Review Agent）
产物打包智能体（Artifact Agent）
```
但现有设计中：
- 编码智能体不直接生成代码
- 评审智能体不直接执行代码评审

实际调用链路为：
```
编码智能体 → ClaudeCode能力实现
评审智能体 → Codex能力实现
```
该分层设计的收益：
1. 保留原有智能体编排调度能力
2. 维持能力（Skill）抽象层设计
3. 底层模型可无感知替换
4. 面向未来架构扩展友好
实现业务逻辑与任意厂商模型解耦。

## 四、各模块权责边界
### 1. 编码智能体（Coding Agent）
#### 负责事项
- 子任务规划拆分
- 会话上下文聚合拼装
- 提示词组装生成
- 发起对应能力调用
- 能力返回结果校验

#### 禁止事项
- 不直接修改项目文件
- 不直接执行系统Shell指令

### 2. 评审智能体（Review Agent）
#### 负责事项
- 代码评审任务规划
- 代码风险点分析
- 问题分类梳理
- 代码质量打分评级

#### 禁止事项
- 不直接改写业务源代码

### 3. ClaudeCode能力（ClaudeCodeSkill）
#### 负责事项
- 拉起并调用Claude Code命令行
- 执行代码生成、文件修改
- 执行项目单元测试
- 执行已授权的Shell指令

#### 禁止事项
- 不可直接修改智能体运行状态
- 不可直接变更任务运行状态

### 4. Codex能力（CodexSkill）
#### 负责事项
- 拉起并调用Codex命令行
- 源代码评审解析
- 代码变更Diff分析
- 输出标准化评审报告

#### 禁止事项
- 不可修改文件所有权配置
- 不可篡改全局调度状态

## 五、调用执行规范
能力运行时通过**进程拉起方式**调用外置编码智能体。
### Claude Code调用示例
```bash
claude -p "
Implement login API.

Requirements:
...
"
```
Claude Code支持通过 `-p` 参数以SDK风格传入指令调用。

### Codex调用示例
```bash
codex --auto-edit
```
或
```bash
codex "Review this diff"
```
Codex命令行提供代码评审、自动代码编辑两种工作模式。

## 六、能力注册配置规范
```yaml
skills:
  claude_code:
    enabled: true
    command: claude
    timeout_seconds: 180

  codex:
    enabled: true
    command: codex
    timeout_seconds: 180
```

## 七、智能体与能力绑定配置
```yaml
agent_bindings:
  coding_agent:
    skills:
      - claude_code

  review_agent:
    skills:
      - codex
```

## 八、工作区隔离约束
每次能力调用分配独立隔离工作目录：
```
workspace/
 ├─ task_001/
 ├─ task_002/
 └─ task_003/
```
外置编码智能体仅允许在被分配的任务目录内操作，**禁止跨任务目录访问文件**。

## 九、安全约束规则
### 强制禁止行为
外置编码智能体禁止：
- 访问任务回放数据库
- 访问系统指标数据库
- 修改资源所有权规则
- 修改运行时全局配置

### 强制遵守规则
外置编码智能体必须：
- 限定在所属工作目录内操作
- 遵从目录所有权管控规则
- 遵从全局文件锁调度约束
- 遵从调用超时时间限制

## 十、异常故障处理
由能力运行时统一管控超时与重试策略：
```yaml
timeout:
  max_seconds: 180

retry:
  max_attempts: 3
```
所有调用异常统一归类为四类错误码：
```yaml
MODEL_ERROR     # 模型侧异常
TIMEOUT_ERROR   # 调用超时异常
PROCESS_ERROR   # 进程启动/运行异常
VALIDATION_ERROR # 返回结果校验失败
```

## 十一、架构演进路线
### 当前落地形态
```
AgentHub
    ↓
系统子进程调用
    ↓
Claude Code / Codex CLI
```
### 未来演进形态（分布式）
```
AgentHub
    ↓
能力运行时(Skill Runtime)
    ↓
远端工作节点资源池
    ↓
Claude远端工作实例
    ↓
Codex远端工作实例
```
架构升级无需改动上层业务代码。
